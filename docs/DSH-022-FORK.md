# DSH 0.2.2-rc.5 适配与验收

本地候选包为 `dsh-agy-link-0.6.96-dsh022.1.tgz`，基于上游 0.6.96（a2e68fa）。适合需要使用 AGY 多账号、同时在角色团队里调用 DSH 工具的用户。

## 选择与安装

1. 先在独立 DSH profile 中试用。要接入正式端，先记录当前 profile 的插件启用状态和模型选择。
2. 对目标 profile 安装本地包，例如 `dsh plugin --profile web add "$HOME/.dsh/local-bundles/dsh-agy-link-0.6.96-dsh022.1.tgz"`。Desktop 选择其对应的 profile。通过插件管理确认启用 dsh-agy-link，在其宿主配置中设置 `mcpBridge: true` 后重启该宿主。
3. 在设置中选择 Antigravity 提供方的模型。角色设定透传采用默认值 `forwardSystemPrompt: true` 与 `cloakSystemPrompt: false`。已有自定义配置会继续生效。模型调用 DSH 工具仍需遵守当前会话的宿主权限、审批与工具准入。
4. 正式切换时在同一 profile 中只启用一个提供相同 Antigravity 模型的适配器。可先停用旧适配器，保留其包和配置以便回退。回退时停用 Link 并重新启用原适配器，再选择原模型。两个插件间的账号库或热会话迁移未经验证。

## 0.6.90-dsh022.2 的历史验收范围

| 场景 | 方法与结果 |
| --- | --- |
| 模式投影 | 用正式发行的 DSH 0.2.2-rc.5 在空白临时 profile 中启动宿主。Standard、Cordis、PTC、Minimal 的桥工具目录均与当步模型目录一致。PTC 仅暴露宿主投影的 `run_code`。Minimal 仍可能包含该 profile 全局注册的工具。 |
| 外部 MCP | 四种模式均经真实 stdio 桥、`chrome-devtools-mcp@1.13.0` 与隔离 Chrome 成功取得页面列表。PTC 从 `run_code` 调用内部工具。执行错误可返回给调用方。 |
| 团队协作 | 四个并发席位（含队长）经真实 role-team、Link、ACP 协议和 MCP 桥分别验明会话 ID、各自的角色设定及长期经验和花名册。四席均能调用任务板和外部 Chrome 工具。补充宿主集成测试覆盖发消息、团队定时工具及角色培养写入。 |
| 恢复与热更新 | 合成用例覆盖热会话角色指令更新、账号切换重建、连续多条待处理汇报、旧截图占位与当前图片保留、摘要与当前输入分界。 |
| 共存 | 独立 Chrome 中打开团队工作台、角色库与设置中的 Antigravity 账号管理页。未记录到页面异常或控制台错误。 |
| 自动化 | 类型检查、依赖架构、模块预算和构建通过，1782 项回归测试通过。 |

本次使用本地 ACP 协议对端代替 Google 云端模型。它记录实际收到的输入，并经插件注册的 stdio 桥发起工具调用。真实 Google 登录、跨账号令牌刷新、云端模型是否遵从提示，以及原生审批弹窗的人工点击均未验收。上线前可用专用测试账号补验这些环节。

启用反向桥时，每个活跃会话使用专属 ACP 进程，路由还会区分账号与运行配置。这样能确定每次工具调用的归属，代价是并发会话越多，占用的进程与内存也越多。账号并发调度和空闲回收仍按插件配置运行。
